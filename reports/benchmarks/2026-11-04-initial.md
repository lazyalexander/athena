## Follow-up: DeepSeek API, 2026-11-05

The original DeepSeek provider used `previous_response_id`, but DeepSeek's Responses API is stateless. A live tool round trip failed with `No tool call found for tool output with call_id`. Athena now retains and sends the full input/output history for DeepSeek. The live `get_time` tool round trip succeeded after the change; OpenAI's stateful path remains separate.

With the same temporary τ-bench adapter, `deepseek-chat` as the Athena agent model and simulated user, airline task IDs `0 1 2 3 4` (one trial each, max 30 steps, substring communication scorer) scored **4/5**. Task 1 failed its database check. All five runs terminated normally and there were no infrastructure errors. Raw results: `/private/tmp/athena-tau2-bench/data/simulations/athena-deepseek-airline-5/results.json`.

### Task 1 failure analysis (2026-11-05)

Task 1 explicitly requires **not** cancelling reservation `Q69X3R`. The domain policy sets the current time to 2024-05-15 15:00:00 EST. The reservation tool returned `created_at: 2024-05-14T09:52:38`, about 29 hours and 7 minutes earlier. It is economy with no insurance, and the cancellation reason is a change of plan. None of the policy's cancellation exceptions applies. The model stated that a booking made on the previous calendar date was "within the last 24 hours" and called `cancel_reservation`. The tool does not enforce the business rule; the database changed and the official DB check correctly failed. The two read-action matches were diagnostic only, not a passing score.

The first adapter put the domain policy in the initial user message. A controlled rerun put it in the Responses API's system instructions. The model made the same elapsed-time error and cancelled the reservation; reward remained 0.0. Raw rerun: `/private/tmp/athena-tau2-bench/data/simulations/athena-deepseek-policy-system-1/results.json`. This supports a model decision failure on this task; the policy-placement defect in the temporary adapter was not sufficient to explain the failure.

This five-task smoke test does not use the TUI approval gate and is not comparable with the official full text-v1 leaderboard, which has a frozen task set and official scoring configuration. No leaderboard submission was made.

The reproducible adapter now lives in `benchmarks/tau2/`. It leaves tool execution and policy enforcement to the official evaluator, so the task 1 policy mistake remains visible in the benchmark result. Separately, Athena's `ToolRegistry` now supports a per-call `beforeExecute` check for real tools; `examples/booking-window.ts` illustrates a 24-hour check using authoritative booking data and a clock. That example is not wired into τ-bench and does not implement the full airline cancellation policy.

The repository adapter passed an official CLI dry run and completed a live task 1 run with `deepseek/deepseek-chat` as both agent and user simulator, substring scoring, and a 30-step limit. It again scored 0.0 with a failed DB check and normal user stop; raw result: `/private/tmp/athena-tau2-bench/data/simulations/athena-repo-adapter-task1-v2/results.json`. This confirms the adapter can produce a scored result, but remains a single-task smoke test.
