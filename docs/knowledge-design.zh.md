# 应用知识与动作决策

## 目标与边界

Athena 是通用 agent harness。Workspace 是共享文件和权限边界；session 保存独立的对话与模型状态。业务政策和变化中的业务数据由应用负责。Athena 只提供检索文本、获取工具观察、计算时间间隔，以及执行前检查工具调用的通用机制。航空规则不进入 `src/agent/` 或评测适配器。

## 三层结构

| 层 | 归属 | 当前机制 | 局限 |
| --- | --- | --- | --- |
| 知识 | 应用或插件 | 可选的 `ATHENA_KNOWLEDGE_DIR` 与 `search_knowledge(query)` 返回片段、文件名和 SHA-256 文档版本 | 词面匹配；模型仍需主动检索并理解条款 |
| 事实 | 应用或插件的工具 | 现有 `ToolRegistry` 和 MCP 工具返回实时观察 | 数据是否新鲜、权威由工具所属方保证 |
| 决策与执行 | 模型，然后是工具所属方 | 通用提示要求核对规则和事实；`elapsed_time` 计算准确间隔；可选 `beforeExecute` 拦截不合格调用 | 提示不能保证推理正确；校验只能执行所属方实现的规则 |

TUI 的轮次授权与业务资格独立。批准不会跳过 `beforeExecute`：每次 `ToolRegistry.call` 都会重新检查。拒绝或校验失败时不会调用 `execute`。应用应以权威状态和合适时钟实现自己的校验；`examples/booking-window.ts` 只演示一个条件，不是完整的取消政策。

## 数据流

1. 应用将受版本控制的 Markdown 文档放在当前工作区内，并将 `ATHENA_KNOWLEDGE_DIR` 设为该目录。这是可选配置；默认不加载领域知识。
2. 模型检索相关条款，通过领域工具获取变化中的事实。知识检索结果是来源文本，不是可执行指令，也不能证明当前事实。来源版本可用于追溯当时返回的内容。
3. 修改状态前，模型依据观察到的事实核对适用规则；有时间界限时可使用 `elapsed_time`。工具所属方还可以在实际操作前执行权威的 `beforeExecute` 校验。拒绝会作为工具错误返回，模型可解释原因或选择其他路径。

`elapsed_time` 要求带明确 UTC 偏移的 ISO 8601 时间，返回秒数和小时数，不判断业务资格。2024-05-14 09:52:38−05:00 至 2024-05-15 15:00:00−05:00 的间隔为 104,842 秒，约 29.12 小时。

## 评测与后续计划

- **已完成：** 通用执行前接口、工作区知识检索、时间计算、模型通用指引，以及重复授权、拒绝／失败、来源边界和时区计算测试。
- **下一步：** 在实际应用或插件包内接入业务政策和数据工具，以权威状态测试允许及拒绝路径；在轨迹评测中检查模型是否找对条款、使用正确事实。现有单元测试不能证明模型行为。
- **基准评测：** 官方 τ-bench 适配器保持不接入工作区知识或业务校验，用于原始模型诊断。若评测带校验的系统，应单独报告工具、提示、规则实现、任务集及原始结果。单题 smoke run 不是榜单成绩。

## 已知局限

词面检索可能漏掉改写后的问题，也可能返回无关段落。SHA-256 版本只能标识文档内容，不能证明政策正确。`beforeExecute` 是接口，不保证与外部业务数据库的更新构成原子事务；并发变化和最终服务端校验由应用负责。目前尚无真实模型运行能证明它会稳定使用新的知识和时间工具。
